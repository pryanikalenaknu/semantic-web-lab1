# Лабораторна робота № 1 — RDF та SPARQL

Побудова RDF-графу освітньо-наукової програми підготовки магістрів
за спеціальністю **F2 «Інженерія програмного забезпечення»**
(факультет інформаційних технологій, КНУ імені Тараса Шевченка).

Дисципліна: **Принципи, методи зв'язування даних у застосуваннях Семантичної павутини** (ОК4).
Група: **ІПЗм-11**.

## Джерело даних

ОНП «Інженерія програмного забезпечення», ID ЄДБО 9112, розглянуто Вченою радою
24.03.2025 (протокол № 9), введено в дію наказом ректора № 342-32 від 25.04.2025.

Використано таблицю 2.1 (перелік компонент), розділи 6–7 (компетентності та програмні
результати навчання) і матриці відповідності 4, 5 і 6.

### Правило пріоритету джерел

ОНП є єдиним джерелом істини для складу програми та атрибутів рівня програми:
код компонента, офіційна назва, кількість кредитів, форма підсумкового контролю,
вид компонента, а також усі три матриці відповідності.

Робочі програми навчальних дисциплін як джерело атрибутів рівня програми не
використовуються: вони містять розбіжності з ОНП (титули ОК4 і ОК8 вказують освітній
рівень «бакалавр», анотація ОК8 називає дисципліну вибірковою, тоді як за ОНП обидві
є обов'язковими компонентами магістерської програми).

Неоднорідні атрибути — доступні лише для частини компонент (викладач, кафедра
компонента, семестр, години, теми, література) — до графу не вносяться взагалі.
Граф лишається однорідним: кожен компонент описано однаковим набором властивостей.

Правило зафіксовано в графі через `dcterms:source` на кожному твердженні про
компоненти, компетентності та результати навчання.

### Зчитування матриць

ОНП є сканованим документом без текстового шару. Матриці 4, 5 і 6 витягнуто
програмно: детекція ліній сітки таблиці за проєкціями чорних пікселів, потім
підрахунок заповненості кожної комірки. Результат звірено візуально на збільшених
фрагментах сторінок. У матриці 6 виявлено артефакт сканування — вертикальну смугу
вздовж правої межі в рядках ОК3–ОК8, що імітувала мітки в колонках ПРН21.1–21.3;
візуальна перевірка підтвердила порожні комірки, артефакт відкинуто.

## Склад графу

| Показник | Мінімум за завданням | Факт |
|---|---|---|
| типів сутностей | 5 | 11 |
| екземплярів сутностей | 20 | 99 |
| типів зв'язків | 5 | 16 власних |

**Типи сутностей:** університет, факультет, кафедра, освітня програма, освітній
компонент, компетентність, програмний результат навчання, форма контролю, група,
підгрупа, студент.

**Повторно вжиті словники:** Schema.org, Dublin Core Terms, SKOS, FOAF,
W3C Organization Ontology, OWL.

Студенти синтетичні (27 осіб, по 9 у трьох підгрупах). Реальні прізвища
одногрупників у публічний репозиторій не вносяться.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
brew install graphviz              # macOS; необов'язково, лише для graf_zriz.png

python build_graph.py              # -> onp.ttl, onp.jsonld
python queries.py                  # виконання всіх SPARQL-запитів
python visualize.py                # -> graf_zriz.png, graf_povnyi.html
python wikidata_link.py            # -> onp_z_wikidata.ttl
```

Або відкрити `lab1.ipynb` — блокнот проходить усі пункти завдання послідовно
й показує текст кожного запиту разом із результатом.

## Що замінити перед здачею

| Файл | Рядок | Замінити на |
|---|---|---|
| `build_graph.py` | `BASE = "https://example.org/onp/"` | власний домен репозиторію |
| `wikidata_link.py` | `USER_AGENT = "...USERNAME..."` | свій логін GitHub |
| `lab1.ipynb` | титульна комірка | ПІБ і посилання на репозиторій |

User-agent має бути описовим і містити контакт: політика Wikimedia блокує
неописові user-agent відповіддю HTTP 403. Кирилиця в заголовку неприпустима —
заголовки HTTP кодуються latin-1.

## Зв'язок із Wikidata

| Ресурс власного графу | Ресурс Wikidata | Предикат |
|---|---|---|
| `onp:KNU` | `wd:Q84151` | `owl:sameAs` |

Обидва URI позначають ту саму реальну організацію, тому твердження про тотожність
денотатів коректне. `rdfs:seeAlso` було б слабшим, ніж дозволяють дані;
`skos:exactMatch` описує відповідність понять, а не окремих об'єктів.

rdflib підтримує ключове слово `SERVICE`, проте у функції `evalServiceQuery`
жорстко зашитий заголовок `user-agent: rdflibForAnUser` без можливості
перевизначення. Тому дані отримуються через SPARQLWrapper із власним user-agent
і вливаються в локальний граф, після чого виконується один запит до об'єднаного графу.
